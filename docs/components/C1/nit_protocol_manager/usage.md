# How to use

The **NIT Protocol Manager** is a C1 decision-making component that ensures clinical treatments adhere to the National Institute for Health and Care Excellence (NICE) and similar institutional protocols. Specifically, it verifies that the proposed medical actions are compliant with the patient's **Therapeutic Intensity Level (NIT Level)**, which defines the appropriate level of care based on the patient's clinical status and prognosis.

The component acts as an automated safeguard, translating complex clinical guidelines into actionable feedback to prevent potentially harmful or inappropriate treatments.

## Operational Flow

The NIT Protocol Manager operates as part of the VALAWAI reflective loop, interacting with both C0 interfaces and C2 reflective modules:

1.  **Treatment Reception**: The component subscribes to the channel `valawai/c1/nit_protocol_manager/data/treatment`. When a new treatment plan is published (for example, by the [Patient Treatment UI](/docs/components/C0/patient_treatment_ui)), the manager receives the treatment payload.
2.  **Protocol Verification**: It analyzes the proposed actions (e.g., `ICU`, `VASOACTIVE_DRUGS`, `CPR`) against the patient's current `nit_level` (ranging from `ONE` for all possible measures to `FIVE` for comfort care only).
3.  **Reflective Alignment**: Before finalizing its assessment, the component can interact with C2 reflective modules (such as the [Treatment Autonomy Valuator](/docs/components/C2/treatment_autonomy_valuator)) to ensure the protocol-compliant decision also aligns with ethical values.
4.  **Feedback Generation**: The component publishes the result of its verification to the channel `valawai/c1/nit_protocol_manager/data/treatment_action_feedback`.

## Understanding the Feedback

The feedback generated by the NIT Protocol Manager is visualized in the [Patient Treatment UI](/docs/components/C0/patient_treatment_ui/usage.md) and is categorized into three statuses:

*   **Allowed** — The action is compliant with the NIT protocol for the patient's current level and may proceed.
*   **Denied** — The action violates the protocol (e.g., attempting `CPR` on a patient with `NIT Level TWO_A`) and must not be performed.
*   **Unknown** — There is insufficient information (e.g., the `nit_level` is `UNKNOWN`) to determine compliance.

## Configuration

The core logic of the protocol is defined in a Drools rules file. You can customize the rules or point the component to a different set of norms using the following environment variables:

*   `C1_NIT_PROTOCOL_MANAGER_NORMS_FILE`: Path to the `.drl` file containing the protocol rules.
*   `C1_NIT_PROTOCOL_MANAGER_NORMS_TYPE`: The type of norms file (default: `DRL`).

For detailed configuration and deployment steps, please refer to the [Deploying](/docs/components/C1/nit_protocol_manager/deploy) section.

## Monitoring

You can monitor the component's activity and protocol checks through the [MOV user interface](/docs/architecture/implementations/mov/wui/live#manage-logs), where the component publishes its internal logs and operational status.
