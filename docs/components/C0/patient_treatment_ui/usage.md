# How to use

The Patient Treatment UI is a web-based C0 component developed for a VALAWAI
project [demonstration](/docs/demonstrations/treatment) that showcases the
architecture in a realistic patient care setting. It simulates the functionalities
a real system would offer to medical professionals — streamlining access to
patient information, supporting personalized treatment planning, integrating
automated protocol verification, and visualizing treatment value alignment — so
that the potential of the VALAWAI architecture can be experienced in a single
interface.

> **Not for clinical use.** This component is a proof of concept. Because medical
> data is governed by stringent privacy regulations, the UI simulates a doctor's
> interaction with a hospital system using synthetic data rather than real patient
> information. Within the simulated environment it acts as a combined sensor
> and actuator: it "senses" user input (doctor actions) and "actuates" changes in the
> VALAWAI system, serving as the primary interface through which doctors interact
> with the architecture during the demonstration.

For a step-by-step, end-to-end walkthrough, see the
[treatment demonstration](/docs/demonstrations/treatment). The underlying
channels and message formats are described in the
[Services](/docs/components/C0/patient_treatment_ui/services) section.

The UI groups its capabilities into two core functionalities:

*   **Patient Management** — registering, viewing, updating, searching, and
    removing patient records.
*   **Treatment Planning** — defining, assigning, and monitoring personalized
    treatment plans, and reviewing the feedback on protocol adherence and
    treatment value alignment.

Each is described in detail below.

## Patient Management

The patient view lists the patients that have been registered, as shown below.
At the top of the view you can search patients by name or add a new one. Below the
search box, the matching patients are listed; on the right of each row, a menu
button opens a menu to view, edit, add a treatment to, or remove the patient.

![The list of patients](/img/components/c0/patient_treatment_ui_patients.png)

To add a new patient, use the control at the top of the view. A form appears, as
shown below, in which you give the patient a name and describe the patient's
current status. The status criteria you define here are the same criteria that
form a treatment's `before_status` and `expected_status`; the full list of fields
is documented in the
[Services](/docs/components/C0/patient_treatment_ui/services) section.

![A form to add or edit a patient](/img/components/c0/patient_treatment_ui_patient.png)

## Treatment Planning

The treatment view lists the treatments that have been defined, which you can
search by patient. A treatment is created from the patient view: open the menu on
the patient's row and choose *Add treatment to patient*. On the right of each
treatment row, a menu button lets you view or remove the treatment.

![The list of treatments](/img/components/c0/patient_treatment_ui_treatments.png)

Defining a treatment is a short, guided process of four steps:

 1. **Confirm the patient's current status.** Review the status recorded for the
    patient and confirm that it is the one the treatment should start from.
 2. **Select the treatment actions.** Choose the series of actions to apply to the
    patient (for example, `ICU`, `VASOACTIVE_DRUGS`, or `CPR`).
 3. **Define the expected status.** Describe the status you expect the patient to
    reach once the actions have been applied.
 4. **Confirm and add the treatment.** Review the definition and add the treatment
    to the patient.

![A form to add a treatment](/img/components/c0/patient_treatment_ui_add_treatement.png)

After a treatment is added, open it from the treatment view to see the feedback
that other components of the VALAWAI system produce about it. This feedback
combines the defined actions, their expected outcomes, and the system's
assessment into a single, holistic picture.

> **Note.** Feedback is generated by the C1 and C2 components. A treatment has no
> feedback until those components are running and have evaluated it. Start them —
> see the [treatment demonstration](/docs/demonstrations/treatment) — and use the
> reload control on the treatment to refresh the results.

The feedback covers two dimensions:

*   **Protocol adherence** — how well each treatment action follows the relevant
    medical protocol (for instance, the NIT protocol), reported by the
    [NIT Protocol Manager](/docs/components/C1/nit_protocol_manager).
*   **Value alignment** — how well the treatment aligns with the ethical values of
    [beneficence](/docs/components/C2/treatment_beneficence_valuator) (acting in
    the patient's best interest),
    [non-maleficence](/docs/components/C2/treatment_nonmaleficence_valuator)
    (avoiding harm),
    [autonomy](/docs/components/C2/treatment_autonomy_valuator) (respecting the
    patient's choices), and
    [justice](/docs/components/C2/treatment_justice_valuator) (ensuring fairness).

Together, they simulate the integration of automated decision support and
value-awareness into a VALAWAI application, helping doctors make more informed,
ethically sound treatment decisions.

![A treatment with its feedback](/img/components/c0/patient_treatment_ui_treatment_plus_feedback.png)

The central section shows NIT protocol compliance for each treatment action, a
critical safeguard for patient safety and adherence to best practices. The status
of each action is indicated as one of:

*   **Allowed** — the action has been reviewed and is compliant with the relevant
    protocols and guidelines, so it may proceed without protocol-related concern.
*   **Denied** — the action violates one or more protocols and *must not* be
    performed. This acts as a safety mechanism that prevents potentially harmful
    actions.
*   **Unknown** — the protocol verification system lacks sufficient information to
    determine compliance. In this case, further investigation, expert
    consultation, or protocol clarification is needed before the action can be
    considered, so the doctor should proceed with caution.

The bottom section visualizes the treatment's alignment with the four core ethical
principles — **beneficence**, **non-maleficence**, **autonomy**, and
**justice** — as a horizontal bar chart. Each bar ranges from -1 (no alignment,
extending to the left, indicating a potential ethical conflict) through 0
(neutral) to +1 (complete alignment, extending to the right). This lets the doctor
quickly assess the ethical implications of the plan and confirm that it reflects
these fundamental values — a prerequisite for responsible, patient-centered care.
